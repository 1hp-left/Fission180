## Versioned migration

The `openfusion-native` identifier and millimetres remain unchanged. New saves use **version 2** to persist identities, graphs, expressions, parameters, output IDs and the selected backend. Version 1 is readable through an explicit in-memory migration. Each old extrusion index is resolved against its original profile array **before** region discovery. A legacy selection that gains inner loops, or an unsupported/ambiguous arrangement, is rejected; no input file is rewritten by Open/migration. A deliberate successful Save writes the new version. Version 2 is not readable by the former version-1-only executable.

Tests cover an old index 1 after an earlier primitive, rejection of ambiguous nested selections, stable reordering/removal, and a 200-edge legacy polygon. These checks cannot recover selection intent already lost in a historically edited file.

## Kernel execution and limits

`kernel::SolidKernel` is the explicit boundary, selected by persisted `Document.backend`. **OCCT remains the default**, remains linked, and retains STEP/STL export. File-menu backend selection rebuilds the document as an ordinary transaction. Unsupported Rust work returns an error without calling OCCT; no implicit conversion/fallback exists.

The independently written `kernel/native.rs` implements a limited **Rust analytic** backend:

- Millimetre numeric domain ±1,000,000; linear tolerance 1e-7 mm, relative policy 1e-10, angular policy 1e-10 rad. Application minimum dimensions remain 1e-5 mm. These are Fission choices, not measured Fusion tolerances.
- Exact line/full-circle geometry, plane/cylinder surfaces, vertices, edges, oriented coedges/loops and faces. Validation checks endpoint/curve/surface incidence, closed loops, IDs and two opposed coedge uses per edge. Native solids expose immutable topology. General trimmed curved surfaces, general arcs and healing are absent.
- Linear extrusion on XY/XZ/YZ, positive/negative distance and translated origins; nonconvex planar polygon/rectangle/circle regions with disjoint holes. Exact analytic volume, area and bounds; display tessellation is separate and refinement never changes those measurements.
- Explicitly scoped Booleans: same-solid identities, disjoint solids, box intersection, through-slab box subtraction including split/empty results, compatible collinear box joins, and a contained through-all region cut in the same extrusion frame. General curved intersections, partial-depth curved cuts and arbitrary box unions/cuts return unsupported errors.
- Operation provenance and body-scoped face/edge references. Rust meshes carry those references and desktop picking chooses the nearest face/visible edge. OCCT topology naming is still absent. Display triangle sorting remains an approximation without a dedicated depth-buffered CAD pass.

The split fixture yields two 2700 mm³ pieces at depth 5; the annular 40×30×5 fixture yields `6000 - 125π` mm³. Tests compare both backends' volume/area/bounds at 1e-5, exercise negative/translated cases and 30 deterministic size/translation cases, integrate oriented display-shell volume with an explicit chord-error allowance, and corrupt topology to test rejection. The **test-only** interoperability adapter reconstructs OCCT edges from Rust B-rep curves/vertices/loops, compares volume/area, writes STEP and reimports it. This is independent-kernel checking, not a completed Fusion import/export exchange. The production Rust backend deliberately rejects STEP/STL export; no replacement gate is declared passed.

`cargo run -p fission180-core --example acceptance_corpus -- <output-directory>` writes/reopens eight version-2 documents with explicit backend measurements. Retained `fixtures/measurements.json` covers rectangle, annular region, split cut and parameter edit on each backend. Its split case uses depth 6 and therefore reports two 3240 mm³ pieces; the depth-5 acceptance is a separate regression test.
