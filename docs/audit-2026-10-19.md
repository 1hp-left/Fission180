# Independent Fusion parity audit — 2026-10-19

**Verdict: full 1:1 parity is not established. The current implementation has demonstrated functional gaps and a reproduced file-overwrite defect.** No product subsystem passed an end-to-end Fusion equivalence assessment in this audit. OpenFusion builds and performs some real solid operations; that is a narrower result.

This audit changed no application source or tests. It read the requested guidance and investigation documents, inspected current source, built and ran the current Rust desktop app, operated Fusion and OpenFusion with Computer Use, rechecked shipped-artifact identities with REA, and ran independent geometry probes. Existing reports and tests were treated as claims to examine. Screenshots record visible states; they do not certify geometry or internal algorithms.

## What the successful checks actually establish

`cargo fmt --all -- --check`, `cargo check --workspace`, and `cargo test --workspace` all returned exit 0. Seven tests passed (4 core, 1 reference integration, 2 desktop); doc-tests ran zero tests. Logs are retained as `cargo-*.log` and `cargo-results.json`. The current Rust desktop executable also built successfully and was operated live. The archived TypeScript runtime was not used.

The reference integration fixture already contains numeric distance **6**; it compares OCCT output to numeric constants and self-imports the resulting STEP. It does not enter `2 * 3 mm` into either application, exercise Fusion, validate expression persistence, or prove cross-kernel exchange. Independent probes broadened coverage beyond the passing suite and found failures listed above.

The failed split-cut `Session::replace` probe preserved exact serialized document, 6000 mm³ volume and undo availability. That is positive **OpenFusion-only** rollback evidence. It does not cover asynchronous GUI file state, preview cancellation races, every kernel exception or tessellation failure. Worker code commits/builds before meshing; a meshing error yields an empty display mesh, so all-path last-good display retention is not established.

Current optimized benchmark: 40 × 30 × 5 extrusion, 10 mm bore subtraction, tessellation, 21 iterations. First iteration **11.253 ms**; 20 warm iterations report **9.5819 ms** median, **9.0761–10.5204 ms** range; analytic/self-STEP volume **5607.3009183012755 mm³**. Intel i7-13620H host; other apps/audit work were running. This first iteration is not an OS-cold startup measurement. No Fusion timing, UI latency, frame-time distribution, memory or large-assembly comparison was obtained. Evidence: `openfusion-benchmark.log`; benchmark source defines its timer boundaries.
